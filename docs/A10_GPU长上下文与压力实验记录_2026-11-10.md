## KV 预算敏感性

`kv_budget_L4096_A10_20261110_140823.tar.gz` 的 SHA-256 为 `9d876bce1b15ffc081792f41b50361760d1fdd371bb800df623c880f38f286c6`。0.6、0.75 各有 3 个独立 vLLM 进程；0.9 使用上述压力扫描的 3 个进程。九份 JSON 的模型 revision、输入 token ID 哈希、GPU UUID 和软件版本一致，批量 16/32/64 全部成功。

| `gpu_memory_utilization` | 日志中可用 KV 池 GiB | 批量 64 平均 token/s | 批量 64 平均设备峰值 MiB |

三档 KV 池大小随预算增加，批量 64 都成功，因此这组负载尚未揭示预算导致的容量边界。吞吐的小幅差异不应解释为预算增加带来的确定性能变化；三档按 0.6、0.75、0.9 顺序运行，可能受运行顺序和设备状态影响。

## 解释限制

- 这是完整推理引擎 A/B，包括调度、算子、编译和缓存策略差异，不能把吞吐差异单独归因于分页。
- `nvidia-smi` 采集的是设备已用显存峰值，vLLM 按预算预留 KV 池；两侧显存数字不能直接相减为分页节省量，也不能当作 KV 内部利用率。
- vLLM 日志有 Numba 与 NumPy 版本不匹配的可选模块导入警告，以及 `_gumbel_sample_kernel` 的推理期 Triton JIT 提示；全部批次完成，但保留其潜在时延干扰。
- 此 A10 数据的软件版本和 GPU 均不同于已有 Colab T4 数据；两组分开报告，不合并求均值。
