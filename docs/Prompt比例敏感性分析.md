# Prompt 比例敏感性分析（正式主实验采用 50%）

`L` 已确定为 prompt token 与生成 token 的总缓存长度。正式主实验采用团队确认的 50% prompt 比例。为检查结论对该假设的敏感度，保持 800 条请求的到达时间、持续时间与总长度不变，仅把 prompt 分别设为总长度的 25%、50%、75%。各轮完整 CSV、SVG 和配置文件位于 `review_outputs/sensitivity/<比例>/`。这些均为 CPU 仿真结果。

| prompt 比例 | 2000 块：逐步扩页 OOM | 3000 块：逐步扩页 OOM | 3000 块：时间加权占用率 | 当前扫描网格零 OOM 首个容量 |
|---:|---:|---:|---:|---:|
| 25% | 24.9% | 0.8% | 69.6% | 6000 |
| 50% | 34.6% | 8.6% | 76.8% | 6000 |
| 75% | 39.9% | 16.2% | 80.8% | 6000 |

prompt 越长，请求到达时需要的 KV 块越多，因此逐步扩页方案在本负载下的低容量失败率上升。连续预留和一次性分页仅使用总长度 `L`，其结果不随拆分比例改变。此处 6000 是离散扫描网格的首个零失败容量，不代表精确阈值。

正式合成负载已采用 50% 作为约定假设，同时保留三档敏感性结果。ShareGPT 轨迹实验应按所选模型 tokenizer 实际计算每轮 prompt/output token 数，不强制套用 50%。
